# Instalación local por rol

Todos: Windows, Git, GitHub con escritura e identidad git configurada. Castilla: Python 3 estándar para validador, Git; SQL Server local/SSMS y VS al trabajar DDL e integración. Poma/Cueva: Visual Studio Community + extensión SSIS, SQL Server local y SSMS. Basualdo: VS + Analysis Services Projects, SSAS Tabular aparte, SQL Server Developer si hace falta motor local, SSMS. Ángel: Power BI Desktop; SSAS accesible solo para probar Live. No todos instalan todo. Anotar versiones realmente instaladas; compatibilidad pendiente de comprobación.

Usar `BI_OLIST` y esquemas que se aprueben. Servidor/instancia, puerto, autenticación, `CSV_ROOT` y rutas se configuran localmente; `.env.example` ilustra nombres, no conecta automáticamente. No fijar rutas absolutas del perfil de usuario, equipo personal ni credenciales en fuentes. Developer es académica/no productiva; Express por sí sola no incluye SSAS.

Descargar manualmente desde Kaggle, aceptar condiciones y anotar fuente/fecha/versión; no subir archivos. Inspeccionar encabezados, codificación, delimitador, decimal, fechas, quoting, nulos y claves antes de fijar parseo SSIS. Desarrollo distribuido usa SQL local y fixtures sintéticas de nueve fuentes; bases no se comparten por Git. Integración y conexión Live requieren servicio SSAS real y acceso seguro acordado, jamás puertos abiertos a internet. Para actualizar contratos a APROBADO hacen falta evidencia real de los nueve CSV y PR revisado por Castilla y los integrantes afectados.
